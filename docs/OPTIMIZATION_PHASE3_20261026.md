## 为什么这样写，如何学习

建议先读 `src/backends/onednn/onednn.cpp` 的 `ConvPlan::init`，再读 `run`：

1. `init` 为给定形状和卷积参数创建计划。oneDNN 选择内部布局。
2. 用 `dnnl_memory_desc_equal` 比较完整描述符。形状相同不代表布局相同，不能只比较维度。
3. 完全相同：`run` 将当前张量指针绑定到已有 memory 对象，直接执行。
4. 不同：继续分配内部缓冲并执行已有 reorder，再执行卷积。
5. 输出布局不同时重排回公开 NCHW 布局，调用者接口保持一致。

三个布尔量 `direct_x/direct_w/direct_y` 对应输入、权重、输出。没有张量内容缓存，也没有按模型名称、层号或具体尺寸特判。权重仍每次绑定当前地址，因此训练更新和 `data()` 写入仍生效。动态库缺少可选的描述符比较符号时保留原重排路径。

通过 `ZNN_NO_ONEDNN=conv_direct` 可以诊断关闭此优化；该开关只用于对照，不要求应用维护两种配置。

## 本轮 100 帧对照

相同 RGB、权重、benchmark，FP32，640，8 CPU 线程，5 次预热；所有后端串行。时间包含预处理、传输、前向和 CPU 输出，不包含文件读取和解码。

| 后端 | 旧版均值 ms | 新版均值 ms | 结论 |
|---|---:|---:|---|
| CPU | 189.695 | 189.031 | 约 0.35%，不足以确认稳定加速 |
| CUDA | 11.732 | 11.975 | GPU 算子未修改；不解释为优化收益 |
| Vulkan | 25.771 | 25.515 | GPU 算子未修改；不解释为优化收益 |

这说明消除完全相同布局的重排只是小优化，不能代替真正的跨算子布局贯通。原来的内部 blocked/NHWC 与外部 NCHW 转换仍然存在。

四图轮换后，独立串行复测结果如下（`candidate/stable_*.csv`，期间未并发构建或运行回归）：

| 后端 | 帧数 | 均值 ms | P99 ms | 最大 ms | 超过 33.33 ms 帧数 |
|---|---:|---:|---:|---:|---:|
| CUDA | 1000 | 11.388 | 14.325 | 15.367 | 0 |
| Vulkan | 1000 | 25.489 | 27.696 | 28.463 | 0 |

逐帧文件已核验帧数与四图轮换序列；这些结果说明此短时间窗口内没有长帧，不代表历史 Vulkan 长帧已修复。首轮 CPU 四图 300 帧均值 191.490 ms；仍远未达到 640 实时要求。

## 多图与逐帧记录

`UNIFP_BENCH_RGB_LIST` 指向文本文件，每行是额外一张 RGB24 文件的绝对路径。所有额外图像必须与主输入使用相同的宽高、stride。主图加额外图像按顺序轮换。`UNIFP_BENCH_FRAMES_CSV` 指定逐帧结果文件，记录帧号、图像编号和各阶段耗时。

本轮主图加三张 PPM-100 真实图像；后者仅为性能实验在测试前调整到 1080×1273，原数据未修改。这不是精度评估。来源和 RGB 哈希记录在 `build/optimization_phase3/inputs.json`。

从 ZInfer 目录复现（输出目录必须不存在）：

```powershell
../UniFP/scripts/bench_rgb.ps1 `
  -Weights ../UniFP/runs/ftk/abs_12000.ufp `
  -Rgb build/perf_audit_20261026/input.rgb `
  -Width 1080 -Height 1273 -Stride 3240 `
  -RgbList build/optimization_phase3/inputs/list.txt `
  -Output build/optimization_phase3/repeat `
  -Iterations 1000 -Sizes 640 -Backends cuda,vulkan
```

脚本的 `manifest.json` 记录输入、权重与 DLL 哈希；`*.frames.csv` 保留时序，不能只看排序后的分位数。缺失文件、截断输入、CSV 写入失败会返回错误。逐帧样本保存在内存中，内存量随测量帧数增长；本批没有做进程内存泄漏验收。

## 下一批的边界

先定义显式的推理权重快照：与训练参数分离，快照拥有自己的存储，不能向调用方暴露其可写 Tensor；更换快照后使执行计划失效。CPU/CUDA/Vulkan/Metal 共用这一契约，后端分别实现预打包。当前公共 Tensor 数据指针仍然可写，不能将普通 Tensor 的 `requires_grad(false)` 误当作不可变保证。

随后做 CPU 权重预打包与布局传播。每一步都先验证权重更新、形状变化、生命周期和训练回归，再测模型收益。没有证据的收益预测不标记为完成。
